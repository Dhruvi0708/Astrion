# Document Storage

Phase 1.5 stores document files. It does **not** parse them or extract anything — `processing_status` stays `registered`.

## Backends

| `ASTRION_STORAGE_BACKEND` | Use | Notes |
|---|---|---|
| `local` (default) | Development | Files under `ASTRION_STORAGE_LOCAL_ROOT` (default `./var/storage`, git-ignored). Writes go to a temp file then are atomically renamed. |
| `s3` | Production | Any S3-compatible store (AWS S3, MinIO, R2). Requires `ASTRION_S3_BUCKET`; optional `ASTRION_S3_ENDPOINT_URL`, `ASTRION_S3_REGION`, `ASTRION_S3_ACCESS_KEY_ID`, `ASTRION_S3_SECRET_ACCESS_KEY` (otherwise boto3's default credential chain). Objects are written with `ServerSideEncryption=AES256`. Install with `pip install -e ".[s3]"`. |

Both implement `StorageBackend` (`put`, `open`, `exists`, `delete`) in `backend/app/storage/`.

## Keys and metadata

Storage keys are generated by the server and never contain user input:

```
ws/<workspace uuid hex>/doc/<document uuid hex>/<sha256[:16]><.ext>
```

The layout is deliberately compact (≤ 96 characters): an earlier, longer layout exceeded the 260-character Windows path limit under a deep storage root, which the Playwright upload test caught. The source isn't part of the key; a document's source is recorded in PostgreSQL.

Every key is checked against a strict pattern before any backend touches it, and the local backend additionally verifies the resolved path stays inside the storage root. PostgreSQL `documents` records `storage_backend`, `storage_key` (unique), `original_filename` (sanitised, display only), `content_hash` (SHA-256), `byte_size` and `media_type`. The key itself is never returned by the API; clients see `has_file`.

## Upload validation (`POST /api/v1/sources/{id}/documents/upload`)

1. Caller must own the source's workspace (else 404).
2. Filename sanitised: directory parts stripped (POSIX and Windows), control/format characters (e.g. RTL override) removed, unsafe characters replaced, ≤ 200 chars.
3. Extension allow-list: `.pdf .txt .md .csv .json .html .docx .xlsx` (else 415).
4. Declared content type must be compatible with the extension (else 415).
5. Size streamed and capped at `ASTRION_STORAGE_MAX_UPLOAD_MB` (default 50) → 413. Empty files rejected.
6. Content sniffed: `%PDF-` for PDF, ZIP signature for DOCX/XLSX, valid UTF-8 without NUL bytes for text types.
7. SHA-256 computed while streaming; stored with the canonical MIME type.
8. If the database write fails, the stored object is deleted (no orphans).

## Download (`GET /api/v1/documents/{id}/content`)

Owner-only. Always `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, `Cache-Control: private, no-store` — an uploaded HTML file can never execute in the API origin.
